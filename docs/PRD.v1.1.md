## ✅ v1.1.0 要做的事

### 1. 登录 / 注册
- **方式**：邮箱魔法链接（输入邮箱 → 点邮件里的链接 → 自动登录）
- **首次使用 = 自动注册**（邮箱没注册过就创建账号，注册过就登录）
- **退出登录**按钮在右上角

### 2. 云端数据
- **用 Supabase**（免费版：500MB 数据库 + 5万月活用户）
- **数据库表**：和 v1.0 数据结构对齐
  - `todos`（待办）
  - `habits`（习惯列表）
  - `habit_records`（每天打卡记录）
  - `moods`（心情日记）
- 每条数据带 `user_id`，**严格隔离**（朋友看不到你的）

### 3. 一次性数据迁移
- 登录成功后，主页顶部出现**黄色提示条**
- 文案："检测到你有 5 条本地待办，是否导入到云端？"
- 点"**导入**" → 把 LocalStorage 数据迁移到云端 → 提示消失
- 点"**跳过**" → 也能用，只是从零开始

### 4. 保留 LocalStorage 作为离线缓存
- 联网时同步到云端
- 离线时仍能看（写操作排队，恢复网络后上传）

## ✅ 验收标准

v1.1.0 完成时，以下 6 条全部通过：

1. **注册**：第一次输入邮箱 → 收到邮件 → 点链接 → 登录成功
2. **退出**：退出按钮可点 → 回到登录页
3. **再登录**：输入同一邮箱 → 收到新邮件 → 点链接 → 数据都在
4. **数据写入**：加一个待办 → 刷新页面 → 待办还在
5. **跨设备**：A 设备加待办 → B 设备打开 → 能看到同一个待办
6. **本地导入**：v1.0 时代的 LocalStorage 数据登录后能一键迁移到云端

## ⚠️ 风险 / 已知挑战

- **邮件进垃圾箱**：QQ 邮箱 / 163 邮箱可能把 Supabase 邮件当成垃圾邮件
- **网络慢**：首次加载要从云端拉数据，可能有 1-2 秒延迟
- **离线编辑冲突**：两台设备同时改同一待办，最后保存的赢
